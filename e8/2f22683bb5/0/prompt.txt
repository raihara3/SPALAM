## Critical Review: Drift Reduction for Featureless Planes

### Findings

**1. [Medium] Division by zero in `getRecoveryBlendFactor` (`PlaneModelPersistence.ts:114`)**

```typescript
return Math.min(1.0, this.recoveryFrame / this.recoveryBlendFrames);
```

If `recoveryBlendFrames` is set to `0` via options, this produces `Infinity` (or `NaN` when `recoveryFrame` is also 0). While `Math.min(1.0, Infinity)` would clamp to 1.0, a `0/0` case yields `NaN`, which would propagate through the lerp calculation at SPALAM.ts line 1231-1232, causing the plane position to become `NaN` and visually disappear.

**Recommendation**: Add a guard in the constructor or in the method itself:
```typescript
if (this.recoveryBlendFrames <= 0) return 1.0;
```

**2. [Medium] Confidence decays indefinitely toward zero but never fully expires (`PlaneModelPersistence.ts:67-68`)**

During DROUGHT, `confidence` is multiplied by `0.995` every frame. At 30fps, after 10 seconds (300 frames), confidence is `0.995^300 = ~0.22`. After 60 seconds, it is `0.995^1800 = ~0.00012`. The value asymptotically approaches zero but never reaches it, meaning `isConfidenceSufficient()` will eventually return false, but the locked model itself is never released (the `locked` object remains allocated and stale). If the user moves the camera to a completely different scene during a long DROUGHT, recovery could snap the plane back to an irrelevant position from minutes ago.

**Recommendation**: Add a maximum DROUGHT duration or explicitly set `locked = null` when confidence drops below the minimum threshold:
```typescript
public updateDuringDrought(): void {
  if (!this.locked) return;
  this.locked.confidence *= this.confidenceDecayRate;
  if (this.locked.confidence < this.minimumConfidenceForRecovery) {
    this.locked = null;
  }
}
```

**3. [Medium] State machine: upward transition counter not reset on downward transitions (`FeatureQualityMonitor.ts:62-64`)**

When the state transitions (e.g., POOR -> DROUGHT), `sustainedUpwardFrames` is reset to 0 at line 64. However, this reset only happens when `this.state !== previousState`.
