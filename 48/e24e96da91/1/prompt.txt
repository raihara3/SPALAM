## Finding 6 [Informational] -- Baseline scale calculation correctness

**File:** `/Users/aihara/10_dev/my/SPALAM/src/tracking/DistanceTracker.ts`, lines 472-479, 503-504

The old code normalized `initialDistance` by dividing by `currentScale` at pair creation time: `initialDistance = distance / currentScale`. The new code stores the raw `distance` as `initialDistance` and snapshots `baselineScale = currentScale`. Then at scale computation time: `scale = (currentDistance / initialDistance) * baselineScale`.

Mathematically: if at creation time the "true" scale is `S_base`, and the measured distance is `d_init`, then later when distance is `d_current`, the absolute scale is `(d_current / d_init) * S_base`. This is equivalent to the old formula: `d_current / (d_init / S_base) = (d_current * S_base) / d_init`. The two formulations are algebraically identical.

The new approach is actually more numerically stable because it avoids a division at pair creation time that could introduce floating-point error that compounds. The baseline snapshot approach also makes the code more readable and debuggable.

**Assessment:** The math is correct. This is a good change.
